## Why I’m building it

Database structure is useful context, but getting it from different systems means dealing with different connectors, naming conventions and metadata. With irides, I’m exploring how to make that information available through one interface, both to people and to applications.

AI tools are one use case: an assistant needs real table and column information before it can reason usefully about a database. Providing that context does not guarantee a correct answer, but it gives the application something concrete to work with.

## What it does

irides inspects database structures, represents their metadata in shared Python models and exposes that information through REST APIs and MCP tools. A web interface lets people browse and annotate the metadata. A command-line client provides another way to inspect it.

Longer scans run in a worker through Redis Streams. Optional AI-generated descriptions are kept separate from the schema metadata. The project also supports exporting documentation as Markdown and Open Knowledge Format bundles.

A typical workflow is to configure a database target, scan its tables, browse the resulting metadata and make that context available to another tool. The repository includes configuration and usage examples.

## What I’m exploring

The project brings together database introspection, background jobs, shared data models and interfaces for AI applications. One important boundary is the distinction between facts read from a database and descriptions generated by a model.

## Current state

irides is in active Alpha. Interfaces and capabilities may change. The repository is the source for current setup instructions, supported connectors and development status; it also distinguishes implemented storage from planned backends.
